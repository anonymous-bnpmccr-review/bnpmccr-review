
# bnpmccr

`bnpmccr` is an R package for **Bayesian nonparametric multivariate conditional copula regression with varying coefficients** for **mixed-type multivariate responses**.

The package jointly models:

1. **marginal distributions with varying coefficients**, using natural cubic spline basis expansions with adaptive knot selection, and
2. **covariate-dependent dependence structures**, using a Gaussian copula mixture with **probit stick-breaking process (PSBP)** weights.

This package implements the method described in the accompanying anonymous manuscript.

> Anonymous Authors (2026). *Bayesian Nonparametric Modeling for Multivariate Conditional Copula Regression with Varying Coefficients*.

---

## Main idea

The main fitting function is `fit_bnpmccr()`.

The model is designed for settings in which both of the following may vary with an additional covariate `covT` (for example, age or time):

- the **marginal effects** of predictors on each response,
- the **dependence structure** among multiple responses.

In other words, `bnpmccr` is intended for multivariate mixed-outcome regression problems where a single global copula or a fixed linear marginal model is too restrictive.

---

## Supported response types

The `responseType` argument is a character vector with one entry per column of `Y`.
Current supported types are:

- `"binary"`
- `"ordinal"`
- `"negative binomial"`
- `"binomial"`
- `"Gaussian"`
- `"gamma"`

For example, a six-response model can be specified as:

```r
responseType <- c(
  "binary",
  "ordinal",
  "negative binomial",
  "binomial",
  "Gaussian",
  "gamma"
)
```

## Backend requirements

`fit_bnpmccr()` assumes that the spline utilities and MCMC backend functions are already available in the package namespace.

Required backend functions include:

- `NaturalCubicBasis()`
- `select_knots()`
- `sampleGammaCpp2()`
- `updateCoefficients2()`
- `updateZCurrGamma()`
- `updateDiffLike()`
- `updateZCurr()`
- `compute_Rh()`
- `compute_zeta()`
- `computeZetaGamma()`
- `computeZetaGamma2()`
- `update_Z_star()`
- `updateDPParameters()`

In practice, this means that the spline utilities and the compiled MCMC update functions should be registered properly through `R/` and `src/`.

## Main interface

```r
output <- fit_bnpmccr(
  Y,
  covT,
  predX,
  responseType,
  niter,
  burnin,
  ...
)
```

### Core inputs

- `Y`: `n x m` response matrix
- `covT`: numeric covariate used for varying coefficients and PSBP weights
- `predX`: predictor matrix **without** an intercept column
- `responseType`: response family for each column of `Y`
- `niter`: total number of MCMC iterations
- `burnin`: number of burn-in iterations
- `num_basis`: number of spline basis terms for the marginal model
- `num_basis2`: number of spline basis terms for the PSBP weight model
- `initH`: truncation level for the PSBP mixture

### Commonly used additional inputs

- `tau`, `tau2`: prior scale parameters
- `omegaM`, `omegaC`: knot-selection hyperparameters
- `nTrial`: number of trials for binomial margins
- `negBinomParInit`: initial value(s) for negative-binomial additional parameters
- `AlphaInit`: initial value(s) for gamma shape parameters
- `std`: whether to standardize non-binary predictors and Gaussian margins
- `verbose`: whether to print MCMC progress messages
- `progress_every`: progress reporting frequency

## Quick example

A typical call looks like this:

```r
responseType <- c(
  "binary",
  "ordinal",
  "negative binomial",
  "binomial",
  "Gaussian",
  "gamma"
)

output <- fit_bnpmccr(
  Y = Y,
  covT = covT,
  predX = cbind(predX),
  responseType = responseType,
  niter = 10000,
  burnin = 5000,
  tau = 1e5,
  nTrial = 10,
  negBinomParInit = 1,
  AlphaInit = 10,
  std = FALSE,
  num_basis = 42,
  omega = 0.4,
  initH = 10,
  num_basis2 = 22,
  tau2 = 1,
  sdbeta1 = sqrt(0.1),
  initAlpha = 1e20,
  omegaM = 0.2,
  omegaC = 0.3,
  mean_alpha = 1,
  verbose = TRUE,
  progress_every = 100
)
```

If `verbose = TRUE`, the function prints progress messages every `progress_every` iterations.

---

## Returned object

`fit_bnpmccr()` returns a list with class `"bnpmccr_fit"`.

Common components include:

- `output$B`: posterior draws of marginal regression coefficients
- `output$G`: posterior draws of marginal basis inclusion indicators
- `output$cutPoint`: posterior samples of ordinal cutpoints
- `output$gammaPar`: posterior samples of gamma additional parameters
- `output$negPar`: posterior samples of negative-binomial additional parameters
- `output$alpha_h`, `output$beta2`: posterior draws for PSBP weight functions
- `output$numPi`: saved mixture-weight or component-count information
- `output$R`, `output$Rmat`, `output$D`: copula dependence objects
- `output$d`: posterior draws related to Gaussian marginal scale parameters
- `output$var_z`: proposal variance state
- `output$acceptratio`: family-specific acceptance summary

## Plotting workflow

The toy example for this package typically produces two kinds of plots.

### 1. Marginal coefficient function plots

The coefficient plots are based on `output$B`.
For each response `k` and predictor `j`, the corresponding coefficient block is extracted, multiplied by the relevant basis matrix, and reconstructed as a function of `t`.

So these plots are **coefficient function plots**,
showing

\[
\beta_{jk}(t)
\]

rather than only a single linear predictor curve.

### 2. PSBP mixture-weight plots

Using `output$alpha_h` and `output$beta2`, the probit stick-breaking weights can be reconstructed and plotted as

\[
\pi_h(t).
\]

These plots summarize how the mixture weights vary with the covariate.

## Toy example

For package examples or reproducible simulations, it is convenient to keep a separate script such as:

```text
inst/examples/toy_example_fit_bnpmccr.R
```

A typical workflow is:

1. simulate mixed-type responses,
2. run `output <- fit_bnpmccr(...)`,
3. draw marginal coefficient function plots,
4. draw PSBP mixture-weight plots.

---

## Notes

- The column order of `Y` must match the order of `responseType`.
- If a `binomial` margin is included, `nTrial` must be supplied.
- `predX` should **not** contain an intercept; the intercept is added internally.
- `burnin` must satisfy `burnin < niter`.
- If required backend functions are not available in the package namespace, model fitting will fail.
